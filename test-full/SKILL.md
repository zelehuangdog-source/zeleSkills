# test-full · 全方位测试（后端为主，可选端到端联调）

> **仅手动触发**（`/test-full`）。对本次改动做全方位测试：穷举分支、覆盖中间流程 null、走真实链路调服务接口验证行为。

**五条硬性要求**（细则在括号里的章节，这里只留红线）：

1. **服务没起就派子 agent 用 `start-backend` 起**，不要自己手敲 mvn，也不要把编译日志灌进主上下文。**本地满足不了测试需求就改打 test 环境**（第一步第 4 条），不据此砍用例。
2. **执行前必须先产出用例清单 HTML**（第五步），**但不设确认卡点** —— 生成完、打开完就继续往下跑；唯一会停下来问用户的是 7.0 的可执行性卡点。
3. **接口调用一律异步**：生成脚本 → 后台拉起 → 收结果文件（第七步），不在对话里同步等返回。
4. **只报告、不修**：后端、自有前端、其他系统的页面与后端，测出的问题全部进问题表（第十步），由用户决定改不改。**唯一允许写的代码**：测试驱动后门（第三步）、测试数据 INSERT（第六步）、联调代理配置（只改「指向哪个后端」）。
5. **「环境不通」不是跳过用例的理由**：拉起脚本前做全量可执行性预检（7.0）；跑不了的用例只有两个出口 —— **用户给方案**（解决后重跑预检）或**用户明确接受跳过**（标 `跳过-用户确认`）。自己划掉用例、写「先不跑这些/不适用」、假装跑过，都算违规。

## 零、选择测试强度（先做，不设默认）

**第一步用 `AskUserQuestion` 让用户选测试强度**，不要替用户设默认、也不要自行揣测（细则见第四步）：

- 问题：本次测试做多重？
- 三个选项：
  - **轻度** —— 主流程 happy path + 1~2 条最明显错误路径（必填缺失、数据不存在）。冒烟：链路跑得通吗。
  - **中等（推荐日常默认）** —— 每个对外入口方法体的所有一级分支 + 关键 null + 常见输入边界。
  - **重度（全方位）** —— 穷举所有分支含深层嵌套 null + 全输入边界矩阵。核心/高风险逻辑或上线前把关。

强度只影响**第四步的用例范围**，其余步骤三档一致；数据准备与强度无关（任何档位都「缺数据就造」）。HTML 和总结开头都要注明用了哪一档。

- **同一次 `AskUserQuestion` 里追加第二问**：是否需要覆盖高并发 / 大数据量场景？
  - **不需要**（默认）—— 只跑功能用例。
  - **需要** —— 追加压力向用例：单独产出 `stress-cases.html` 与独立脚本，**默认不执行**，用户确认后才跑（见 4.5）。
- **同一次 `AskUserQuestion` 里追加第三问**：是否需要做**端到端联调**？三档单问（不要额外追问前端状态）：
  - **不做**（默认）—— 只验后端。
  - **仅契约核对** —— 只做 A 层：拿真实响应体 diff **所有消费方**（自有前端、其他系统的页面代码、其他系统的后端调用代码）的类型/字段/可空性。不需要任何页面跑起来。
  - **完整端到端** —— A + B（在真实页面上做数据与交互断言，页面含**其他系统的页面**）+ C（仅自有前端增量组件）。

  选后两档的按 **4.6 节**做：**联调面不限于自有前后端** —— 与本次迭代有交互的其他系统页面/后端都算联调对象。某个对象前置条件不满足时按 7.0 问用户（给方案 / 明确接受降档），用户确认后才降档，并在 `integration-cases.html` 页头和总结里写明实际档位与被跳过的对象。

## 一、确认服务在跑（没起 → 子 agent 调 start-backend）

1. **先探活**：从项目配置（`application-*.yml` / `bootstrap.yml`）拿端口，`lsof -i :{port} -sTCP:LISTEN` 或 curl 健康检查确认已在跑；也可看本地日志 `/tmp/{项目名}-dev.log` 尾部。
2. **没起 → 派子 agent 启动，不要在主流程里自己启**：

   ```
   Agent(
     subagent_type: "general-purpose",
     description: "启动后端服务",
     prompt: "用 Skill 工具调用 start-backend skill 启动 {项目名}（路径 {项目绝对路径}）。
              全程不要把编译日志、启动日志正文回传给我。
              最终只回报三行：1) 是否启动成功 2) 监听端口 3) 失败时的根因一句话 + 日志文件路径。"
   )
   ```

   - 必须走子 agent（编译 + 启动日志上千行，放主上下文会把用例设计挤掉），且**派完立刻继续做第二～六步**，不要干等。
   - 卡点在第七步之前：真正发请求前必须已收到成功回报；回报失败走第九步。
3. 服务已在跑则跳过本步，记下端口继续。
4. **本地服务满足不了测试需求时改打 test 环境，不要据此砍用例** —— 典型情形：本地起不来、缺依赖或要连真实上游、本地资源撑不住批量/压测、需要多实例复现。做法：
   - **部署当前分支到 test**：走 `mt-deploy`（或 `ee-plus`）的 **test 档**。部署影响共享环境，**部署前先在对话里说明**分支/环境/影响面，不静默部署。
   - **拿 test 机器列表**（Plus 三步）：`code/repo/release/list?repository=<仓库>` → `release_detail?release_id=<id>` 取 **test** 档 `template_id` → `/api/templateid/<id>/hosts`。
   - **地址规则**：`/api/**` 可走线下域名 `<svc>.tsp.test.sankuai.com`；`/test/**`、`/backdoor/**`、`/monitor/**` **必须打机器 IP**（`http://<ip>:8080/...`）。
   - **换了环境要重新核预检**：入口可达、鉴权可过要在 test 机器上再过一遍（见 7.0）。
   - 本地起不来且 test 环境也走不通（没环境、拿不到部署权限），才走第九步问用户。

## 三、发现接口入口

测试通过**调用本次测试后端的服务接口**（HTTP/RPC）驱动 —— 后端既可以是本地起的进程，也可以是按第一步第 4 条部署到 test 环境的机器。

1. 从改动的 Controller / 接口推断入口，确定 URL、方法、入参结构、鉴权要求。
2. **没有可直接调用的入口时**（只改了 DomainService / Repository 内部方法）：**写后门接口到 TestController** 把要测的方法暴露出来驱动。
   - 位置：`starter/controller/test/{业务模块}/XxxTestController.java`，复杂逻辑下沉到 `application/backdoor/{业务模块}/XxxBackdoorService.java`，TestController 只做接收/校验/调用/返回。
   - 后门代码**测完保留**作为可复用后门，测完在总结里列出新增了哪些。
   - ⚠️ 新增后门后**服务需重启才生效** —— 同样派子 agent 走 `start-backend`（第一步），不要自己在主流程编译。

## 四、分析分支 → 用例矩阵（按所选强度收放）

读改动源码，按第零步选的档位设计用例。每条用例必须明确四要素，第五步的 HTML 直接由它渲染：

| 要素 | 说明 |
|------|------|
| **做什么** | 一句话描述场景 + 命中的具体分支（带 `file:line`） |
| **依赖什么** | 前置数据（哪张表哪行）、依赖的前序用例、外部服务状态 |
| **怎样算通过** | 具体判定：返回体哪个字段等于什么、DB 哪张表哪行变成什么状态。**不许只写「返回 200」** |
| **入参** | 完整可复现的请求体 / query |

**设计时就把「本环境真能跑」想清楚**：依赖外部服务/中间件的场景先定好可控手段（后门、mock、指向线下实例、造数构造状态），别只写「依赖 X 服务」指望跑时正好通。只能靠真实外部依赖、当前环境打不通的**也要写成用例**，留到 7.0 预检连同降级路径一起摆给用户，**不许在设计阶段就自己划掉**。

**轻度**：只覆盖主流程 happy path + 1~2 条最明显的错误路径（必填缺失、数据不存在）。

**中等**：
- 覆盖每个对外入口方法体里的**所有一级分支**：`if/else`、`switch`、三元、`Optional`、早返回、循环进入/不进入。**不深挖被调用方法内部的嵌套分支**。
- **关键 null**：入参级 null、外部依赖/DB 返回 null（不穷举中间字段组合）。
- **常见输入边界**：空集合、空串、非法值各一发；状态边界：数据存在/不存在。
- **状态机与外部系统按 4.1 逐个覆盖**（每种状态各一条、每种返回各一条），不受「不深挖二级分支」限制。

**重度**：
- **穷举所有分支**，含**每个中间流程字段为 null 的 case**（逐层追进被调方法）。
- 全输入边界矩阵：空集合、空串、超长、特殊字符、负数、零、极值。
- 全状态边界：存在/不存在、已删除/已禁用、首次/重复；依赖边界：外部服务/DB 超时、失败、返回空。
- 4.1 两条强制要求同样适用，且要**叠加组合**（如「处于 X 状态 + 下游返回超时」）。

### 4.1 两条强制覆盖要求（状态机 / 外部系统）

用例范围按档位收放，但这两类**逐个覆盖、不许合并糊过去**。适用档位：**中等及以上必须满足**；轻度只跑主流程那一条，未覆盖的仍在「覆盖情况」里写明（轻度定位就是冒烟，不算违规）。

**① 涉及状态机的，每一种状态各写一条用例**

- 先把状态集合列全：枚举/常量类、DB 状态字段、`status` code 取值域，以及代码里的非法/中间态。
- **每个状态各一条**：「做什么」写明「当前处于 X 状态」，通过标准写清该状态的应有行为（允许哪些动作、拒绝哪些动作、返回体字段）。一个状态有多种进入路径或行为分支的再拆，**不要一条用例覆盖两种状态**。
- 有终止态、回退态、不可逆转移的各自单列。

**② 涉及外部系统的，每一种返回可能各写一条用例**

- 把每个外部依赖（HTTP/RPC 下游、MQ、缓存、第三方、非本地库）的返回可能**列全**：正常成功、业务失败（明确错误码/业务异常）、超时、连接异常/不可达、返回空/null、字段缺失、乱序或重复。
- **每种返回各一条**；**会改变流程走向的返回**（走哪个分支、是否重试/回滚/补偿/落失败态）**必须单独成条**，不许挂在主流程用例里顺带一提。「做什么」写明「下游 X 返回 Y」，通过标准写清应走路径与副作用：重试几次、最终状态、是否回滚/补偿、是否落库、是否告警。
- 这些用例必须**能制造出该返回**（后门/mock/挡板/测试桩）；造不出来的**照样写成用例**，在 7.0 预检里连降级路径一起摆给用户，不要因为造不出来就不写。

## 4.5、高并发 / 大数据量用例（仅当第零步勾选「需要」才做）

与普通用例**完全隔离**（独立 HTML、独立脚本、独立结果文件、独立执行卡点）。设计维度按入口形态裁剪，不硬凑：

- **高并发**：N 个并发打同一接口（`&` 并发 curl 或 `xargs -P`）—— 并发写同一行/并发创建同类资源（唯一键冲突、覆盖丢失）、重复提交/幂等、计数原子性。通过标准**必须含 DB 终态核对**（行数、唯一键无冲突、计数与明细一致），只看 HTTP 200 不算过。
- **大数据量**：批量接口打满上限 + 上限 +1（应被校验拦截）、大结果集分页（总数、首尾页）；通过标准含**耗时记录** + DB 落库行数核对（耗时明显劣化也进问题表）。
- 并发度/数据量按「接口真实上限 + 适度超配」，并在 HTML 里写明为什么是这个量级。

**隔离与卡点**：

- `stress-cases.html` 与 `cases.html` 同目录并列，结构与 5.2 一致，页头注明「⚠️ 压力向 · 默认不执行」+ 预计造数据量与执行影响（写多少行、打多久、会不会影响共享 test 环境他人使用）。
- `run-stress-cases.sh` 结果落 `results-stress.jsonl`、响应体落 `responses-stress/`。
- **默认不执行**：HTML 生成并 `open` 后用 `AskUserQuestion` 问（立即执行 / 暂不执行）；选「暂不执行」属**用户自己**的决定，标「用户暂缓执行」并保持全部「待执行」，随时可喊补跑。
- **选了「立即执行」就不打折**：同样走 7.0 预检、同样做结果条数对账与 `INCOMPLETE` 检查；跑不完一样查原因补齐，或经用户明确接受才可标跳过。

## 4.6、端到端联调用例（仅当第零步勾选后两档时做）

**联调面 = 与本次迭代有交互的所有系统，不限于自有前后端。** 动手前先把联调对象列全，逐个设计用例：

| 联调对象类型 | 典型形态 | 用例关心什么 |
|---|---|---|
| 自有前端 | 本次需求的前端页面 / hook / 组件 | 新数据、新交互是否正确渲染与响应 |
| **其他系统的页面** | 别的系统的前端页面，展示或触发本次改动的数据与能力 | 我们的改动有没有把**它**弄坏（老字段、老语义、可空性变化）；它调我们的接口是否仍合法 |
| **其他系统的后端** | 别的系统作为调用方/消费方：调我们的接口、订阅我们的消息、读我们的库表 | 契约变更后是否还解析得动、是否漏判新枚举、消息体变化能否被正确消费 |

**禁止只测自有前端** —— 其他系统的页面与后端都要单独设计用例：A 层 diff 它的解析模型/字段引用，B 层在它自己的页面上做断言。

### 4.6.1 先列联调对象 + 逐个查前置条件，不满足按 7.0 问用户

**第一步把联调对象列全**（对照 4.6.2 的契约变更点挨个找消费方）：

- **自有前端**：见下方映射表；推不出来就**一次性问用户**（仓库路径 + 分支/工作区）。
- **其他系统的页面 / 后端**：先自己找 —— grep 我们的接口 URL/slug、看调用方流量或依赖方文档、看消息 topic 订阅方、问团队里谁知道；找不出来就**一次性问用户**（对象名 + 页面地址或仓库 + 谁能给环境）。
- 拿不到环境的对象不等于「不存在」：按 7.0 当不可执行项摆给用户，由用户给方案或明确接受跳过。

**逐个对象查前置条件，缺哪项按 7.0 问用户（不许自己降档）**：

| 前置条件 | 怎么查 | 缺了怎么办 |
|---------|-------|-----------|
| 自有前端：仓库 / 已实现需求 / dev server 在跑 | 见下方映射表；fe 仓库 `git log --oneline -20` / `git status` 看本次改动或 grep 后端接口 URL；端口从 `vite.config.ts` / `package.json` scripts 拿后 `lsof -i :{fePort} -sTCP:LISTEN` | 仓库或分支拿不到 → 问用户；未实现 → 按 7.0 问用户（接受降档后 B/C 标「前端未实现，用户确认跳过」）；dev server 没起 → 后台拉起 `pnpm dev` / `npm run dev` |
| 自有前端：代理指向本次后端 | 读 `vite.config.ts` 的 `server.proxy`，target 必须是本次后端（本地端口，或 test 机器 IP/线下域名，见第一步第 4 条） | **阻塞项**：指到别的后端 = 测的不是本次代码。改代理配置（属环境配置，允许改）或问用户 |
| 其他系统：页面 / 后端可达 | 页面 URL 能否用 ego-browser 打开（真实浏览器 + 内网 SSO 免登）、接口能否 dial | 不可达 → 按 7.0 问用户（要账号、要白名单、要谁给环境） |
| 其他系统：链路指向本次环境 | 它配置里我们服务的地址是哪个环境（线下 test 还是线上）。自有前端可改代理；**别人的系统通常改不了配置，就不要硬改** —— 记录实际指向并写进页头 | 指向线上而我们没发线上 = 测不到本次改动，按 7.0 问用户 |

**降档不是你自己能拍板的事**：第零步选了「完整端到端」但前置条件不满足时，把缺的项按 7.0 摆给用户（给方案 / 明确接受降档），不要静默降档，也不要用「环境不通」把 B/C 这笔账糊过去。

### 4.6.2 端到端联调用例的锚点是「契约变更点」，不是后端用例清单

**禁止把后端用例逐条映射成联调用例** —— 后端用例大半是内部逻辑分支（null 兜底、边界值、异常分支），联调对象压根不消费，映射过去就是噪音。正确链路（**每个联调对象各走一遍**）：

```
本次改动（第二步锁定）→ 抽出「对外契约变更点」→ 在每个联调对象里追踪它是否真消费了这个点 → 才生成该对象的联调用例
```

**契约变更点清单**（有哪类抽哪类）：新增/删除/改名接口（URL、method）；请求字段增删改与必填性变化；响应字段增删改、类型变化、**可空性变化**；枚举新增值/改值；错误码新增或语义变化；分页/排序语义变化；字段语义变化（如 `title` 改装 `name`）。

**消费点怎么找（逐个对象）**：

- **自有前端**：fe 仓库 grep 接口 URL 片段、hook 名（`useXxx`）、字段名。
- **其他系统的页面**：有代码就 grep 它的前端仓库；没代码就**从页面反查** —— ego-browser 打开它的页面看网络请求是否打到我们的接口/字段（顺带产出 B 层用例的入口）。
- **其他系统的后端**：grep 它的接口调用代码与反序列化模型（DTO/POJO）、消息消费逻辑读了哪些字段。
- 命中 → 为该对象生成联调用例，记下 `文件:行`（页面记 URL + 请求路径）；没命中 → 在 HTML 里列一行「该对象不涉及」，**写明 grep/看了什么、确认没搜到**，不许静默跳过。

### 4.6.3 三层用例（按验证手段分层，来源当标签）

来源（`回归` / `新增` / `外部系统`）在联调里执行手段完全一样，所以按验证手段分三层，来源当标签打在用例上：

**A 层 · 契约一致性核对（免浏览器，零成本，ROI 最高）**

- 拿 `responses/{caseId}.json` 真实响应体，对照**每个消费方**的类型定义/字段引用/可空性假设做机械 diff（自有前端看 TS 类型，其他系统后端看 DTO/反序列化模型，其他系统页面看它代码怎么读这些字段）。
- 查什么：消费方声明了但后端没返回、后端返回了但消费方没声明、枚举值少判、**消费方按非空用（`data.xxx.yyy`）但后端可能返回 null**、字段名/类型不一致、消息体字段增删后消费方是否还在原位置读。
- 这层**全量做，与强度档位无关**。

**B 层 · 端到端行为验证（需要浏览器；页面可以是自有前端也可以是其他系统的）**

断言两类都要有 —— 只做数据断言会漏掉全部交互问题（点了没反应、状态没同步、按钮不禁用）：

- **B1 数据断言**：ego-browser 打开**涉及的页面**（自有前端，或其他系统里用到本次数据的页面）→ 触发后端真实请求 → DOM 文本/属性与响应体逐字段比。通过标准必须是**具体渲染值** + 无控制台报错 + 无失败网络请求，**不许只写「页面能打开」「没报错」。** 其他系统的页面额外两条：它发给我们的请求参数仍合法（枚举、必填、分页变更后没踩空）；它要展示的我们的数据**没变成空/未定义/占位符**（老字段语义、可空性变化最容易在这栽）。
- **B2 交互断言**：`动作 → UI 状态`，交互行为唯一的责任人。ego-browser 在**涉及的页面**上做动作，用可观测条件断言状态变化：元素出现/消失（`waitForSelector` 或 `page.evaluate`）、属性变化（读 `disabled` / `aria-expanded` / class）、URL 同步（读 `location.search`）、请求发出（`page.on("request")` 或 CDP 断言条数与关键参数）。至少覆盖本次改动涉及的动作，有哪个查哪个：

  | 动作 | 期望状态 |
  |------|---------|
  | 筛选 / 搜索 / 排序 | 列表内容变了、URL query 同步、翻页重置到第 1 页 |
  | 分页 | 页码与总数正确、首尾页边界 |
  | 提交 / 保存 | 期间按钮 disabled + loading，结束后恢复；成功后列表刷新或出 toast |
  | 二次确认 / 危险操作 | 弹确认框；取消不生效 |
  | 表单校验 | 非法输入出提示、按钮不可提交 |
  | 展开 / 收起 / Tab 切换 | 状态保持或按预期重置 |
  | 空数据 / 请求失败 | 出空态或错误态，而不是白屏 / 一直 loading |

  通过标准同样要写**具体状态**（`button[disabled]` 存在、`?level=high` 出现在 URL、出现「暂无数据」文案），**不许只写「点击正常」。**

- 来源标签：`回归` —— 后端改了老接口/老字段，**老页面**（自有或其他系统的）是否还正常；`新增` —— 自有前端本次新写的页面/hook/组件；`外部系统` —— 其他系统的页面/后端调我们、消费我们的消息或数据后是否仍正确（最典型的回归对象）。

**C 层 · 样式核对（截图 checklist，不进用例表；范围仅自有前端增量组件）**

- **只对自有前端增量组件做样式基线核对** —— 其他系统的页面只做「布局没塌、数据没错位」的回归观察（`style-checklist.html` 单独一节，结论只能是「回归观察」，不给「符合/不符合」），别把别人的 UI 拿我们的原型比。
- **基准**按优先级取：① 需求目录的原型 HTML（宽松匹配 `原型*.html` / `增量原型*.html` / `方案与原型*.html` / `ui-prototype*.html`，写明对照第几屏）；② 同模块既有页面（原型缺失时截图老页面做观感对照）；③ 项目 `CLAUDE.md` / 样式 token（颜色间距是否用 CSS Variables 而非硬编码）。
- **粒度落到组件**：先 `git diff --name-only` 拿到改动组件清单，**逐个组件出核对项**（新增的小组件 —— 新 Tag、Tooltip、状态徽标、空态插画 —— 也要有自己的**局部截图**）；整页截图只用来判「布局没塌/没重叠」，细节一律看局部截图。截图覆盖三态：默认态 + 空态/错误态 + 长内容态（用第六步造的数据触发超长文本、超长枚举值、多行）；长页面关键区域单独截（整页长图 Read 进来会被压缩）。
- **核对维度**（按改动裁剪）：布局没塌/不重叠、长文本与超长枚举值不溢出、空态/加载态/错误态齐全且文案中文、数字与日期格式一致、颜色间距用 CSS Variables、与基准及同模块既有页面观感一致。
- **反走过场（不遵守等于没做 C 层）**：每条核对项**必须写依据**（「对照了 `原型-XXX.html` 第 2 屏」），只写「符合」不算；**全项「符合」但零佐证 → 整体标「未核对」，不计通过**；不符合项**必须能对应到截图**（指明哪张、哪个区域），不许写「样式有问题」。

### 4.6.4 执行方式：主 agent 直接用 ego-browser 跑

- **拿 API**：先 `Read ~/.claude/skills/ego-browser/SKILL.md`（它在 `settings.json` 里是 `user-invocable-only`，**Skill 工具调不起来**，但 CLI 能直接用）。**跑法**：Bash heredoc —— `ego-browser nodejs <<'EOF' ... EOF`，页面内代码放进 `page.evaluate()`。
- **一个 TaskSpace 贯穿整场联调**：首次 `taskSpace("{需求名}联调")` 后 print `spaceId`，后续 `taskSpace({spaceId})` 恢复，不要每轮新建；**每个联调对象开自己的 tab**，别在一个 tab 里跨页面来回导航（状态互相覆盖后断言不准）。
- **断言写在 heredoc 里，只 print 一行结论 JSON**：

  ```js
  console.log(JSON.stringify({ caseId: "I03", pass: true, expect: "高风险", actual: "高风险" }));
  ```

  **严禁 print `snapshot()` 全文 / 整页 HTML / 完整响应体**（几万 token 会挤爆主上下文），要细节就落盘再定向 Read。
- **每条断言同时 append 一行到 `integration/results-integration.jsonl`**（heredoc 内 `await import("node:fs/promises")` 写），字段至少 `{"caseId","layer":"A|B1|B2","pass","expect","actual","screenshot"}`；**断言失败/脚本抛错也必须写一行**。
- **截图落盘**：`await page.screenshot({ path: "{产物目录}/integration/screenshots/{caseId}.png" })`，再用 Read 看图。
- **登录态**：ego-browser 接用户真实浏览器，内网站点 SSO 免登直接用 —— **其他系统的页面同样靠它**（一般不需要我们本地起任何东西，直接开它的地址）。要手输登录的页面用 `task.handOff()` 交给用户点。
- **不要试图在本地起别人的系统**：其他系统的页面/后端用它已部署的环境（test 或线上）；造数据造我们自己的库或走我们的后门，别动别人系统的数据，并在用例里写明造的是哪边的数。
- **不要用固定 `waitForTimeout` 碰运气**，用 `waitForSelector` / `waitForFunction` 等可观测条件。
- **B 层交互式跑**（每轮看页面状态再决定下一步），不走第七步那种一次性后台脚本；A 层纯读码，C 层可以一个 heredoc 批量截完再逐张 Read 看图。

### 4.6.5 失败与降级

- 前置条件不满足 → **先按 7.0 问用户**，确认后才降档，并写进 `integration-cases.html` 页头和总结（本次只做了 A 层 / 经用户确认 B 层跳过 N 条 / 某个联调对象整体跳过），不要静默降档、不要假装跑过了。
- 联调测出的问题**同样只报告不修**（硬性要求 4）—— 自有前端、其他系统的页面与后端代码都不改。
- B 层某条失败**先归因再进表**：后端请求在 `results.jsonl` 里过没过？后端过而页面渲染/消费出错 → **消费方**问题（自有前端或某个其他系统）；后端本身就错 → 后端问题（已在问题表里，**不要重复列**）。**归因必须写进问题表的「代码位置」列**。

| 核验项 | 怎么确认 | 不过怎么办 |
|-------|---------|-----------|
| **入口可达** | method + path 在服务里真实存在：读 Controller 映射，或对**只读**接口探测 curl 看是否 404 | 路径写错就改；入口不存在 → 按第三步补后门（需重启，走子 agent） |
| **鉴权可过** | 对比 SSO 配置的 `sso.excludedUriList`，确认路径免鉴权；不免鉴权的要有 token/登录态 | 换等价豁免路径（如 `/test/**` 后门）、拿 token，或进「不可执行项」 |
| **入参可造** | 用例依赖的前置数据已存在或已按第六步造好；依赖的前序用例在脚本里排在其前面 | 补造数、补依赖顺序 |
| **判定依据可得** | 需 DB 核对的用例：先跑只读探测（如 `select 1`）确认 test 库连通、核对 SQL 可跑 | 连不上库 → 按第九步找连接串；找不到问用户 |
| **写操作不撞车** | 写用例的目标行/唯一键不会被现存数据顶掉（唯一键冲突、状态机不允许） | 换唯一值、清场或改用带标记的新行 |
| **外部依赖可用** | 依赖的外部服务/中间件可达；不可达时先找降级路径（线下实例、mock、后门） | **不要直接判「跑不了」**：先找降级路径，再不行就把当前分支部署到 test 环境打 test 机器（第一步第 4 条）；仍不行才进「不可执行项」 |

预检结果落 **`cases-preflight.md`**（与 `cases.html` 同目录），每条一行：用例ID | 可执行/不可执行 | 卡在哪一项 | 解决方案 / 缺什么信息。跑完回填后仍保留。

**不可执行项的唯一出口**：用 `AskUserQuestion` 把全部不可执行项**一次性**摆给用户（合并成一个问题，逐条列用例ID + 卡点 + 你试过哪些方案 + 建议解法），选项固定两个：

- **我提供方案**（端口/token/连接串/前端仓库/环境信息）→ 拿到后解决 → **重跑预检** → 剩余用例全绿才拉起脚本；仍跑不通再问一轮，不要自己拍板跳过。
- **明确接受跳过** → 才可在 `cases.html` 状态列写 `跳过-用户确认`，并在总结里单独列出清单。

**没有第三条路**：不许自己标跳过、不许写「环境不通/先不跑这些」、不许把跑不了包装成「不适用」或「弱化断言凑通过」。

### 7.1 生成 `run-cases.sh`

- **独立用例并发**（`&` 并发拉起，末尾 `wait`）；**依赖链串行**（造数 → 依赖它的用例、写同一行或有先后因果的必须按顺序，先做依赖分析再分组）。
- **不要给 curl 设超时**（别加 `--max-time`）：有些接口本来就跑得久（批量刷数、图计算、同步任务），砍掉是误判成失败；后台异步跑，跑多久都不阻塞。
- **每条用例把结果 append 到 `results.jsonl`**，一行一个 JSON，字段至少：

  ```json
  {"caseId":"C01","name":"...","httpStatus":200,"costMs":153,"ok":true,"error":null,"bodyFile":"responses/C01.json"}
  ```

  curl 本身失败（连不上、超时）也要写一行、`error` 记原因；完整响应体单独落 `responses/{caseId}.json`，不塞进 jsonl。
- **脚本末尾必须自证跑完**：把 `results.jsonl` 行数（含失败行）与用例条数对账 —— 全齐打 `ALL_DONE expected=N actual=N`，有缺席打 `INCOMPLETE expected=N actual=M missing={caseId,...}`。**看到 `INCOMPLETE` 就是「用例没跑完」**：查清缺的为什么没落结果（curl 挂掉、脚本中途退出、依赖用例失败导致没触发、分组写漏），修好重跑补齐；**不许拿 M 条结论当 N 条汇报**。每条例外（跑不了、被跳过）也要落一行 `ok:false` + `error`，静默缺席会被对账抓出来。

### 7.2 后台拉起，同时干别的

```
Bash(command: "bash {产物目录}/run-cases.sh > {产物目录}/run.log 2>&1",
     run_in_background: true)
```

- 拉起后**立刻去做别的事**（继续读源码推导各用例预期、准备 DB 副作用核对 SQL），不要空转轮询；脚本跑完会有 task 通知，届时再读 `results.jsonl`。
- 用例多、想看实时进展时用 `Monitor` 盯 `results.jsonl` 的失败行（filter 要同时匹配成功与失败信号，别只匹配 happy path）。

## 八、判定与回填

- **先对账再判定**：看到 `INCOMPLETE` 一律先补齐重跑，**不许带着缺席行进入判定**。
- **依代码逻辑自行推导预期并判定** —— 读源码推导每条用例的预期返回值/副作用，对比 `results.jsonl` + `responses/` 实际结果判通过/失败；**判定要具体**（不只看 HTTP 200，要校验返回体字段；有 DB 副作用的必须直连 test 库核对）。
- **回填 HTML**：重写 `cases.html`，补「实际结果」「通过/失败」两列，失败行标红并附 `file:line` + 疑似原因；页头加汇总（通过 X / 失败 Y / 跳过-用户确认 Z）。跳过列每行都要能对应到 7.0 预检时用户的明确接受，拿不出确认记录说明流程被违规执行，回去问用户。
- **判完就停手，不要动业务代码**（硬性要求 4）—— 定位到根因也只写进问题表。

### 8.1 端到端联调回填（仅勾选后两档时）

- **顺序：A 层先做（纯读码，快），再跑 B 层** —— A 层查出的可空性变化、枚举漏值、字段名不符直接变成 B 层的重点断言，反过来会白跑一遍。
- 回填 `integration-cases.html`：补「实际结果」「通过/失败」两列，失败行标红并**注明归因**（自有前端 `Xxx.tsx:42` / 后端 `Xxx.java:88` / 其他系统 `其他系统名：XxxPage.tsx:42` 或 `OtherSvc.java:88`）。
- 回填 `style-checklist.html`：逐项写结论 + **依据**；**填不出依据的写「未核对」，不要默认写「符合」**；不符合项要能对应到截图。
- 某个联调对象整体没跑（环境拿不到、用户接受跳过）→ 在页头联调对象清单里标「经用户确认跳过」并写明卡点，**不要让它悄悄从表里消失**。
- 联调问题并入第十步的**同一张问题表**，代码位置列写清是自有前端、后端还是哪个其他系统。

## 九、阻塞处理

遇到阻塞（接口需鉴权/登录态、服务起不来、test 库连不上、端口未知、认不出对应需求文档、**联调对象定位不到 / 其他系统页面或环境拿不到 / dev server 起不来 / 代理或链路没指本次后端**等）：

1. **先尽力自己找** —— 从项目配置、环境变量、启动脚本、本地日志 `/tmp/{项目名}-dev.log` 找端口、连接串、token、鉴权方式；前端侧从 `vite.config.ts` / `package.json` / `pnpm-workspace.yaml` 找端口和代理配置。**本地起不来或满足不了测试需求的，先走第一步第 4 条（部署当前分支到 test 环境）**，不要直接当成阻塞报上来。
2. **找不到再停下来问用户** —— 不瞎猜瞎试可能污染错误环境的操作；把缺的信息**一次性**列清楚问用户（给方案 / 明确接受跳过或降档；降档口径见 4.6.1）。
3. **环境类阻塞不许转化为跳过** —— 服务起不来、库连不上、接口要鉴权、外部依赖挂了，都只允许两种收尾：**用户给方案 → 解决 → 全部用例跑完**，或**用户明确接受 → 标 `跳过-用户确认`**。禁止在请示前就把用例划掉，禁止用「环境不通」「先不跑这些」「本次跳过」收尾，禁止只跑一部分就汇报说测过了。

## 十、产出

- **文件产物**（落 Obsidian 需求文档目录，见 5.1）：`cases.html`（含结果回填）、`results.jsonl`、`responses/`、`run-cases.sh`；勾选压力向时另有 `stress-cases.html`（回填；未执行注明「用户暂缓执行」）+ `run-stress-cases.sh` + `results-stress.jsonl` + `responses-stress/`；勾选联调后两档时另有 `integration/integration-cases.html`（含联调对象清单、回填与归因）+ `integration/style-checklist.html` + `integration/results-integration.jsonl` + `integration/screenshots/`。
- **对话内总结**（简洁，明细看 HTML）：
  - **开头注明**：测试强度档位 + **本次打的是本地还是 test 环境（具体地址/机器）** + `cases.html` 路径；勾选压力向的注明执行状态（已执行 / 用户暂缓）与 `stress-cases.html` 路径；勾选联调的注明**实际档位 + 联调对象有哪几个、各自哪一档（含被用户确认跳过的）** + `integration-cases.html` 路径。
  - **一行汇总 + 执行完整性**：通过 X / 失败 Y / 跳过-用户确认 Z（压力向、联调各自单独一行），并给出脚本对账结果（`ALL_DONE expected=N actual=N` 或补齐重跑后的结果），确认没有任何用例是「没跑」而非「跑过/用户确认跳过」。
  - **跳过清单（Z > 0 时必填）**：跳过的用例 ID + 卡点原因 + 用户在哪一步明确接受；**整体被跳过的联调对象也在此列出**。列不出确认记录的跳过等于流程违规，回去问用户。
  - **联调各层各报一句**：A 契约核对命中几个不一致点（分清自有前端/其他系统）；B1、B2 各过几条（自有前端页面与其他系统页面分别报）；C 样式核对符合 X / 不符合 Y / **未核对 W**（未核对必须报出来，不能混进「符合」），其他系统页面只报「回归观察」。
  - **问题清单（必须是表格，只报告不修）** —— 每个问题一行：

    | # | 问题描述 | 复现用例 | 代码位置 | 预期 vs 实际 | 疑似原因 | 严重度 |
    |---|---------|---------|---------|-------------|---------|-------|
    | 1 | 一句话说清坏在哪 | C03 | `Xxx.java:88` | 期望 A，实际 B | 根因判断 | 高/中/低 |

    - 严重度：**高**=主流程不可用/数据错乱；**中**=边界分支行为不符预期；**低**=提示语、日志、非关键字段瑕疵。表格按严重度从高到低排；一个问题被多条用例命中的合成一行、「复现用例」写多个 ID。
    - 「代码位置」列：后端 `Xxx.java:88`、自有前端 `Xxx.tsx:42`、其他系统 `其他系统名：XxxPage.tsx:42` / `OtherSvc.java:88`，一眼能看出该谁改。
    - **表格之后不要接「我来帮你改」并动手** —— 最多一句话说明「要改的话大概动哪里」，然后停下等用户发话。
  - **覆盖情况**：未覆盖的分支及原因；**状态机逐状态**列出覆盖/未覆盖（哪个状态没跑、为什么）；**外部依赖逐返回**列出覆盖/未覆盖（哪种返回没造出来、为什么、是否已被用户确认跳过）。
  - **本次持久化痕迹**：新增的 TestController 后门接口；造入 test 库的 mock 数据（表、主键、标记）。

## 执行顺序小结

0. 一次问三件（不设默认）：测试强度 + 是否覆盖压力向 + 是否做端到端联调
1. 探活；没起 → 子 agent 调 `start-backend`；本地满足不了需求 → 部署当前分支到 test 环境拿机器地址（第一步第 4 条）
2. 锁范围：对话历史为主、git diff 为辅
3. 找接口入口；缺入口写 TestController 后门（保留，需重启）
4. 按档位出用例四要素；状态机逐状态、外部系统逐返回（4.1）；压力向按 4.5；联调按 4.6（对象列全 → 契约变更点 → A/B/C 三层）
5. 出 `cases.html`（+ 勾选时的 `stress-cases.html`、`integration/*.html`）落 Obsidian 并 `open`，不等回复继续；压力向 HTML 用 `AskUserQuestion` 问是否执行（默认不执行）
6. 直连 test 库查/造数据（加标记、不删）
7. 可执行性预检（7.0）：六项逐条核验，落 `cases-preflight.md`；跑不了的按 7.0 问用户，问完才拉起脚本
8. 生成 `run-cases.sh` 并后台拉起；脚本末尾对账，`INCOMPLETE` 先补齐重跑
9. 读结果判定 → 回填 `cases.html`
10. 联调执行（勾选时）：A → B1/B2（ego-browser 跑自有前端与其他系统页面）→ C（仅自有前端）→ 回填两个 HTML
11. 阻塞先自查、不行一次性问用户；任何阻塞都不转成静默跳过
12. 给简洁总结（档位 + 环境 + 联调档位 + 汇总 + 问题表 + 覆盖情况 + 持久化痕迹）
13. 停手：问题只进表格，后端/前端/其他系统代码都不改
