# Translate Article to Obsidian + 学城

> 翻译外文文章到中文，添加摘要，保存到 Obsidian 仓库，并同步到学城文档。

---

## 元数据

| 属性 | 值 |
|-----|---|
| **name** | translate-article |
| **version** | 1.2.0 |
| **author** | huangzele |
| **description** | 翻译外文文章到中文，自动添加摘要，保存到 Obsidian 并同步到学城文档。用户粘贴文章内容即可完成翻译+摘要+归档+同步。 |
| **triggers** | `翻译文章`, `translate article`, `翻译到obsidian`, `翻译这篇文章` |

## 使用方式

用户调用 `/translate-article` 后，粘贴文章内容（或提供 URL）。Skill 自动完成以下流程（Obsidian 保存 + 学城同步）。

---

## 执行流程

### Step 1：接收文章内容

- 如果用户在调用 skill 时已经粘贴了文章内容，直接使用
- 如果用户只调用了 skill 没有提供内容，提示用户粘贴文章内容
- 如果用户提供了 URL，使用 fetch skill 获取内容

### Step 2：翻译文章

你是一名资深技术译者。你的目标不是"把英文转成中文"，而是**让中文读者读起来像一篇母语者写的好文章**——好懂优先于逐字对应。将文章从原文翻译为中文，遵循以下原则：

#### 核心原则：好懂第一

1. **意译优先，禁止逐句硬译**：理解原句意思后用中文自然表达，允许为可读性重组语序、合并或拆分句子
2. **长句拆短**：英文长句（多层从句、嵌套修饰）必须拆成多个中文短句，每句只表达一个意思
3. **按中文语序重组**：中文习惯先背景后结论、先因后果，不要保留英文的倒装和后置修饰结构

#### 借喻与文化负载词处理

4. **借喻要落地**：英文里的借喻（如体育、军事、烹饪等领域的隐喻，如 play、playbook、home run）不要生硬直译。选择中文读者能自然理解的说法，**首次出现时括注英文原文**，如「实践方案（play）」「战术手册（playbook）」
5. **陌生概念补半句解释**：对中文读者可能不熟的概念，在译文中自然地补上半句解释或译注，不要假装读者已经知道
6. **一词多义看上下文**：同一英文词在不同语境选不同的中文译法（如 play 在戏剧语境是"剧目"、在工程管理语境是"做法/招式"），不要全文统一死译

#### 反翻译腔（机翻味）检查清单

7. **少用"被"字**：能改主动就改主动（"代码被代理生成"→"代理生成代码"）
8. **避免"的……的……"长定语**：定语超过两个"的"就必须拆开或后置
9. **名词化还原成动词**：英文爱用名词（"the transformation of X"），中文用动词更自然（"改造 X"）
10. **代词还原名词**：英文 it/this/they 指代明确，中文直译"它/这/它们"常读不通，必要时还原成指代的名词
11. **连接词减量**：英文靠连接词衔接，中文靠语序衔接。"并且""此外""然而"能省则省

#### 格式与保留项

12. **术语保留**：技术术语保留英文原文，用括号标注中文释义（首次出现时）
13. **格式保留**：保持原文的标题层级、列表、代码块等 Markdown 格式
14. **代码不翻译**：代码块和行内代码保持原样
15. **图片链接先原样保留**：翻译阶段先保持原文图片链接（外部 URL）不变，作为占位，实际本地化在 Step 6 统一处理——不要在这一步就下载或替换

#### 译后自检

16. 翻译完成后，**以"完全没看过原文的中文读者"视角通读一遍译文**：凡是读不顺、需要回读、或要去猜"原文是哪个词"的句子，重译

### Step 3：生成摘要

在翻译后的文章开头添加摘要：

- 摘要长度：3-5 句话，150-300 字
- 摘要内容：文章的核心观点、关键结论、实用价值
- 摘要格式：用引用块 `>` 包裹

### Step 4：组装完整文档

按以下结构组装最终文档：

```markdown
---
title: "翻译后的中文标题"
date: YYYY-MM-DD
tags:
  - 翻译
  - （根据文章内容添加 2-3 个相关标签）
original_title: "原文标题"
original_language: "原文语言（如 English）"
---

> **摘要**：（3-5 句话的摘要内容）

---

（翻译后的正文）
```

### Step 5：确定存放路径

所有通过本 skill 翻译的文章统一放入 `外部文章/` 目录下。

**子目录归类规则**：

`外部文章/` 内部按主题域分子目录。每次插入新文章时：

1. **列出当前子目录**：先 `ls` 查看 `外部文章/` 下已有的子目录
2. **判断归类**：
   - 新文章属于某个已有目录：放入最匹配的子目录
   - 新文章不属于任何已有目录：创建新子目录

文件命名：以日期为前缀，格式为 `YYYYMMDD-标题.md`。日期取 frontmatter 中的 `date` 字段（去掉短横线）。标题使用翻译后的中文标题，去掉特殊字符，空格替换为短横线。

示例：`20260526-Anthropic工作坊-我们如何使用Claude-Code.md`

### Step 6：下载并本地化图片（Obsidian 与学城共用）

**背景**：原文图片大多来自境外图床（如 Twitter/X 的 `pbs.twimg.com`），当前网络下常常无法直连。如果 Obsidian 正文里保留这种外部直链，图片会直接显示不出来。因此必须在保存到 Obsidian **之前**，把所有图片下载到本地并改为相对路径引用；这批本地文件后续同步学城时可以直接复用，不用再下载一次。

1. **提取图片**：从译文正文中找出所有 `![alt](URL)` 格式的外部图片链接，按出现顺序编号。

2. **确定本地存放位置**：`{obsidianRepo}/{分类路径}/assets/`（与仓库现有文章的图片组织方式一致，例如 `外部文章/AI工程方法论/assets/karpathy-agentic-01.jpg`）。首次在该分类下放图片时，先创建 `assets/` 子目录。

3. **命名规则**：优先用有语义的描述性文件名（如 `assets/loop-cover.jpg`、`assets/loop-turn-based.jpg`），图片语义不明确时退化为 `assets/{文章短标题slug}-{序号}.{扩展名}`。

4. **下载策略**（先直连，直连失败再走代理，不要一上来就用代理）：
   ```bash
   # 1. 先尝试直接下载
   curl -sS --connect-timeout 8 -o "<本地路径>" "<图片URL>"

   # 2. 直连失败（超时/连接失败/返回空文件）时，降级走本机代理
   curl -sS --connect-timeout 10 -x socks5h://127.0.0.1:7892 -o "<本地路径>" "<图片URL>"
   ```
   **关键注意**：代理必须用 `socks5h://`（远端 DNS 解析），不能用 `socks5://`（本地 DNS 解析会被污染，导致 SSL 握手失败）。

5. **两种方式都下载失败时**：该图片保留原始外部 URL 不做替换，记录下来，在 Step 9 的最终输出中告知用户"该图片本地化失败，Obsidian 中可能无法显示"。

6. **替换正文引用**：下载成功的图片，把正文中的 `![alt](原始外部URL)` 替换为相对路径 `![alt](assets/文件名)`。

7. **产出**：本地图片文件（已复制进 assets 目录）+ 图片引用已全部替换为本地相对路径的正文 + 一份「本地文件路径 → 原始外部URL」映射表（供 Step 8 同步学城时复用，避免重复下载）。

### Step 7：保存文件到 Obsidian

将 Step 6 产出的本地图片文件保存到 `{obsidianRepo}/{分类路径}/assets/` 目录，再将图片引用已本地化的完整正文写入 `{obsidianRepo}/{分类路径}/{日期}-{标题}.md`。

### Step 8：同步到学城文档（含图片）

在 Obsidian 保存成功后，同步创建学城文档。学城禁止外部图片 URL，需要通过上传流程处理。

#### 8.1 确定学城目标目录

根据文章所归类的 Obsidian 子目录名称，查找配置中 `citadel.categoryMapping` 对应的 contentId 作为 `parentId`。

#### 8.2 创建文档（不含图片）

先将 Markdown 内容中的图片行（`![...](...)` 格式）去掉，用纯文本内容创建文档：

```bash
# 去掉图片行后创建
CONTENT=$(sed '/^!\[/d' <<< "$MARKDOWN_CONTENT")
oa-skills citadel createDocument \
  --title "YYYYMMDD-翻译后的中文标题" \
  --content "$CONTENT" \
  --parentId "<对应目录的 contentId>" \
  --spaceId "4344448" \
  --mis huangzele
```

记录返回的 `contentId`。

#### 8.3 上传图片到文档

**优先复用 Step 6 已下载好的本地图片文件**，直接用 `--image` 参数上传，不必重新下载：

```bash
oa-skills citadel uploadImageToDocument \
  --contentId "<文档ID>" \
  --image "<Step 6 中保存的本地图片路径>" \
  --alt "<图片描述>" \
  --mis huangzele
```

如果某张图片在 Step 6 里本地化失败（没有本地文件），再退回直接传外部 URL 作为最后尝试：

```bash
oa-skills citadel uploadImageToDocument \
  --contentId "<文档ID>" \
  --imageUrl "<外部图片URL>" \
  --alt "<图片描述>" \
  --mis huangzele
```

记录每张图片的映射关系：`本地文件/原始外部URL → 学城CDN URL`。

#### 8.4 将图片插入文档

1. 获取文档的 CitadelMD 结构：
   ```bash
   oa-skills citadel getDocumentCitadelMd --contentId "<文档ID>" --output /tmp/article.md --mis huangzele
   ```

2. 找到图片应插入的位置（根据上下文段落定位），插入 CitadelMD 格式的图片节点：
   ```
   :::paragraph{nodeId="auto-img-N"}
   ![描述](学城CDN URL){width=W height=H}
   :::
   ```

3. 更新文档：
   ```bash
   oa-skills citadel updateDocumentByMd --contentId "<文档ID>" --file /tmp/article.md --mis huangzele
   ```

#### 8.5 如果目录不匹配

当 Obsidian 子目录是新创建的（学城无对应目录），先在学城 `2770220270` 下创建同名目录文档，再将文章创建为其子文档。

#### 8.6 图片处理的特殊情况

- **无图片的文章**：跳过 8.3 和 8.4，直接完成
- **图片上传失败**：记录失败的图片 URL，在最终输出中告知用户，不影响文档创建
- **图片位置定位**：根据原文中图片前后的文本段落内容，在 CitadelMD 中找到对应的 `paragraph` nodeId，在其后插入图片节点

**注意事项**：
- 学城文档标题格式为 `YYYYMMDD-标题`（与 Obsidian 文件名一致，但不含 `.md` 后缀）
- 文档内容不包含 YAML frontmatter，从摘要引用块开始
- 图片上传两种参数：`--image <本地路径>`（优先，复用 Step 6 已下载文件）或 `--imageUrl <外部URL>`（仅当本地化失败时兜底）
- 图片绑定文档权限，必须上传到目标文档本身（不能跨文档引用）
- 创建成功后记录学城文档链接

### Step 9：输出摘要

在对话框中输出：

```
✅ Obsidian 已保存：{文件路径}
✅ 图片已本地化：{N} 张（保存至 assets/，如有图片）
✅ 学城已同步：{学城文档链接}
✅ 图片已同步至学城：{N} 张

摘要：
{摘要内容}
```

如果部分图片处理失败：
```
✅ Obsidian 已保存：{文件路径}
⚠️ 图片本地化：{成功数}/{总数} 张，失败的图片仍为外部链接，Obsidian 中可能无法显示：
   - {失败的图片URL}: {失败原因}
✅ 学城已同步：{学城文档链接}
⚠️ 图片同步至学城：{成功数}/{总数} 张，失败的图片：
   - {失败的图片URL}: {失败原因}

摘要：
{摘要内容}
```

## 注意事项

- 长文章直接翻译，不要分段确认
- 翻译风格偏向技术博客的自然中文表达，避免机翻味
- 如果文章有明确的原文标题，使用翻译后的标题作为文件名
- 如果无法确定标题，从内容中提炼一个合适的标题
- **图片必须本地化**：Obsidian 正文中禁止保留外部图床直链（尤其是 Twitter/X 等境外图床，当前网络下常无法直连，会导致图片显示不出来）。图片必须先下载到 `assets/` 目录、正文改为相对路径引用，见 Step 6
- 图片下载遵循"先直连、失败再走代理"的顺序，代理固定用 `socks5h://127.0.0.1:7892`（必须是 `socks5h` 而不是 `socks5`，否则本地 DNS 解析会被污染导致握手失败）
- Obsidian 本地化的图片文件，同步学城时应直接复用，不要重复下载
- 学城同步失败不影响 Obsidian 保存结果，但需要告知用户失败原因
- 学城文档和 Obsidian 使用相同的分类目录体系，保持一致
