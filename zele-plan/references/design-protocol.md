# 设计协议：穷举闸门

本文件是 zele-plan 的**闸门细则**。目的只有一个：让"写到一半发现设计要推翻"这件事在数学上不可能发生 —— 因为所有路径在动笔前就已经被走过一遍了。

---

## 一、穷举表

在阶段 2 产出，四张表。**此时禁止写任何实现细节**（不要写类名、不要写接口、不要写 SQL）。

### 表 1 · 使用方清单

| 使用方 | 类型 | 说明 |
|---|---|---|
| 运营人员 | 人 | 在治理平台页面操作 |
| 上游归档系统 | 系统 | 通过 Octo 推送归档事件 |
| 定时任务 | 系统 | 每日凌晨全量对账 |

**类型只有两种：人 / 系统。** 内部模块（Service、Mapper、Controller）不是使用方。

### 表 2 · 用例清单

| 编号 | 使用方 | 功能 | 本次是否改造 |
|---|---|---|---|
| UC-1 | 运营人员 | 按在线服务筛选实体列表 | 是 |
| UC-2 | 上游归档系统 | 接收归档事件 | 是 |
| UC-3 | 运营人员 | 导出台账 | 否（但受 UC-1 影响） |

**"本次是否改造"必须显式标注。** 影响但不改造的用例要单列 —— 这类最容易在后期变成"哎呀这里也得改"。

### 表 3 · 路径分解

对每个改造的用例，拆成路径：

| 用例 | 路径 | 触发条件 | 预期结果 |
|---|---|---|---|
| UC-1 | 正常 | 勾选筛选条件且命中 | 返回过滤后列表 |
| UC-1 | 分支 | 未勾选任何条件 | 等价于不筛选 |
| UC-1 | 分支 | 标签组不存在 | 返回空集，不报错 |
| UC-1 | 异常 | 标签服务超时 | 降级为不筛选 + 告警 |

**每条路径都必须写"预期结果"。** 写不出预期结果的路径，说明还没想清楚 —— 这时候去查，不要跳过。

### 表 4 · 模型触点

| 模型 | UC-1 | UC-2 | 读/写 |
|---|---|---|---|
| ENTITY_TAG_REL | ✓ | | 读 |
| LINK_ENTRY_NODE | ✓ | ✓ | 读 |

## 二、遗漏自查清单

穷举表写完后，**逐条**过一遍下面 7 类。这是经验性的高频遗漏点，不是可选项。

1. **使用方漏了**
   - 只想了主使用方？漏了运维、上下游系统、定时任务、数据消费方？
   - 谁**读**这份数据？（不只是谁写）
2. **触发方式漏了**
   - 只想了"用户点击"？漏了定时任务、消息消费、手工补偿、批量刷数、上游推送？
3. **数据状态漏了**
   - 只想了"数据存在"？漏了不存在、软删、历史脏数据、并发写？
4. **兼容性漏了**
   - 老数据没有新字段怎么办？改造期间新旧逻辑并存怎么办？需要刷数吗？
5. **口径漏了**
   - 计数口径和列表口径是否一致？（"列表 3 条、计数 5 条"是经典事故）
   - 权限过滤是否在两个地方都加了？
6. **副作用漏了**
   - 这个改动会不会让**别的已有功能**行为变化？（尤其共享查询、共享缓存）
7. **失败路径漏了**
   - 外部依赖挂了怎么办？部分成功怎么回滚？重试幂等吗？

## 三、冲突自查

穷举表内部必须自洽。逐条检查：

- [ ] **同一字段的语义假设是否一致** —— 两条路径对同一个字段的理解不能不同
- [ ] **同一份数据的生命周期假设是否一致** —— 谁创建、谁修改、谁删除，在各路径里说法要一致
- [ ] **读方与写方是否对齐** —— 写进去的格式，读的地方认得出来吗
- [ ] **有没有两条路径的预期结果互相矛盾**

发现冲突 → 现在解决。这是**最后一个便宜的时机**。

---

## 四、反推模拟（阶段 3 的收口）

设计定稿后，拿最终的数据模型，把表 3 的**每一条路径**用一个具体例子走一遍：

> "假设运营人员勾选了 `APPKEY_STATUS=NORMAL`：请求进到查询 → 按 appkey 关联到 Service 节点 → 查 `entity_tag_rel` 命中 3 个 → 这 3 个的 id 进 IN 子句 → 返回 3 条。**模型够用吗？** 够。"

走不通的情况，举例：

- 需要按某个维度过滤，但模型里没这个字段 → 回阶段 2
- 需要在写入时校验，但写入方不经过这个模型 → 回阶段 2
- 两条路径要用同一个字段表达两种含义 → 回阶段 2

**反推模拟不通过就回阶段 2 重做。** 此时文档还没写，返工成本接近零 —— 这正是闸门存在的意义。

## 五、完成信号

能一口气回答下面三个问题，且答案之间不打架，才算过闸门：

1. **任意一条路径**：数据从哪来 → 经过什么 → 变成什么 → 到哪去？
2. **失败时**：这条路径失败了，谁会看到什么？会不会留下脏数据？
3. **不改造的用例**：本次改动会不会让它行为变化？

答不上来 → 继续查，别开始写。
